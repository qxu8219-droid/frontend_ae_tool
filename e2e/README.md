# T05–T07 browser checks

T17 opt-in real SDK checks use `playwright.resilience.config.ts`, owned by `backend/scripts/validate_resilience.py`; they are not included in the default browser checks below. Modes are `soak` (1800 wall-clock seconds, native WebSocket), `matrix` (controls/faults plus recording), and `recording` (targeted screen-recording retry only). The launcher gates success on source hashes, cleanup, and actual per-frame recording analysis. See [commands and evidence scopes](../../backend/docs/resilience-validation-v1.md). The recorded screen is a lossless Chrome CDP PNG sequence with timestamps/SHA256; numerical reference templates are independent of application drawing code. No extra browser or FFmpeg installation is required for that path.

Run `npm run test:e2e` from `frontend`. Both mock and real-mode projects run by default; `E2E_REAL=0 npm run test:e2e` runs only mock coverage. The installed Playwright version is pinned in the package lock. Tests use `/usr/bin/google-chrome` with GPU acceleration disabled and temporary Playwright browser contexts, without browser downloads or personal profiles.

Playwright owns Vite mock port 5183, real-mode Vite port 5184, and the contract-only ASGI service on port 18010. Existing servers are never reused; occupied ports cause a failure. The ASGI command clears `PYTHONPATH` and `PYTHONHOME` and starts only the contract application. It does not start IsaacSim or a worker. Playwright stops its servers after the run.

All actions use visible controls. The read-only diagnostics supply observations only. The oracle reads the selected snapshot and actual canvas pixels in one synchronous evaluation, independently decodes all 32 capture-ID bits and 32 CRC bits, checks synthetic source values, and samples the rendered progress bar. An independent canvas rasterizes expected time, source-angle, and six joint-value labels for pixel comparison with the actual displayed text. It does not import the production stamp, renderer, runtime, or store. Multiple unique capture IDs are sampled in each replay scenario; paused captures must keep advancing while time and joint values remain constant.

The suite covers lifecycle controls, failed upload, absent log, missing-channel provenance, worker recovery, 650 ms video/data delay, WebSocket reconnect, delayed-resource teardown, and real mode's explicit backend 503 without MSW or synthetic fallback. Additional workbench tests cover mapping validation, upload inspection and explicit activation, rejected replacement files, timeline final targets, source-frame index seek, current-canvas curve cursor during 650ms delay, group folding, event filtering/seek, and checkbox channel selection with apply/cancel. The healthy performance test renders 28 joints and four historical curves together. It checks Mock frontend behavior only; it does not validate real H.264, WHEP, IsaacSim, GPU rendering, or final product acceptance.

Each test writes `observations.json` and `final-page.png` under `output/test-results`; failures also retain Playwright traces and screenshots. Browser HTTP requests outside loopback are blocked and reported as failures. No HTTP or WebSocket success responses are fabricated by the test suite: mock traffic is handled by the application's native MSW installation.

T18 复现入口与环境前提见 [交付手册](../../backend/docs/delivery-v1.md)。倍速控制用例在每轮归零，避免自然结束后再点击禁用的暂停；真实合成日志用例的逐值核对采用普通断言，保留原精度、采样频率和像素检查，并在性能门槛判断前保存测量值。失败输出仍保留，不以重复运行覆盖。

## Light workbench regression

The light UI keeps the original behavioral and pixel checks, with independent expected coordinates for the 1600×920 canvas and light palette. Navigation helpers open/close the actual import, precise-seek, annotation and close-confirmation layers; assertions are not replaced by direct state mutation. `light-workbench.spec.ts` covers active/candidate metadata isolation, candidate recovery, close cancellation, channel draft cancellation, guarded keyboard seek and pending-log frame identity. New evidence is kept under `output/light-workbench/`; the default real-mode project still checks the contract-only 503 boundary, while actual IsaacSim uses the separate real launcher.
