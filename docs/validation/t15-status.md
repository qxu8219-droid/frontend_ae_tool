## 实际浏览器证据

最终扩展探针：`backend/outputs/t15/real-5/`；摘要：[t15-evidence.json](t15-evidence.json)。由 `backend/scripts/validate_frontend.py` 启动本次拥有的 API、SDK、Vite 和系统 Chrome，测试 `e2e/real-replay.spec.ts`，不是 Mock 或预录视频。

- 通过正式 UI 创建会话、上传 12 秒/241 样本/28 关节＋底盘的 CSV、检查映射并显式激活，随后执行播放、0.1x/10x、暂停、秒数定位、前后原采样点、连续拖动 2→7→4 秒、停止、末尾与重播。
- **59 次实际 canvas 采样**核对完整图像 ID/CRC、对应快照、可见日志时间、源轮角、6 个关节数字、底盘数字和进度条；全部 28 关节源值及 SDK 读回与保存的原 CSV 独立插值对照一致。曲线游标另以实际像素核验。
- 健康移动窗口约 4 秒，实际共同呈现 **18.84fps**，29 次采样的最大捕获到呈现读取间隔 **178.99ms**。这是本机短窗口浏览器结果，不能外推为长期负载或异地主机网络结论。
- 测试层将原生 Worker 的已解码帧交付额外延后 **700ms**，不改变视频、目录或数值；5 个移动采样的延迟为约 **788–836ms**，仍全部同帧匹配。延迟中的暂停、连续定位到最终 4 秒及撤销延迟后的恢复通过，资源计数保持有界。该注入不是 RTC 丢包或独立 SEI 网络延迟仿真。
- 预扫描事件可提前查看，但 0 秒“本轮已触发”保持为空；历史查询不冒充当前告警。WS 真实连接被测试代理关闭后建立新连接，恢复完整元数据和同帧画面。
